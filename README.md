# Democratic Leadership Accountability Project

### Your Voice. Your Government. Your Right to Be Heard.

**Created by [Justin Harris](https://github.com/Jdhrrs)**

An independent, open-source civic engagement project designed to help citizens communicate concerns, advocate for political accountability, and make their voices heard by elected officials.

---

## About This Project

Citizens should never feel that their voices don't matter.

The Democratic Leadership Accountability Project was created to make civic participation more accessible by providing a customizable Google Apps Script framework for communicating with elected officials and public offices.

Whether advocating for new leadership, expressing dissatisfaction with political decisions, or demanding greater accountability, citizens deserve accessible tools to participate in the democratic process.

This project is independently developed and is not affiliated with the Democratic National Committee, the U.S. House of Representatives, or any political organization.

## Features

- Google Apps Script integration.
- Customizable email messages.
- Configurable recipient lists.
- Optional scheduled communication.
- Message templates that users can personalize.
- Manual start and stop controls.
- Sending limits and safeguards.
- No separate hosting or server required.

## Getting Started

### Requirements

Before getting started, you will need:

- A Google account.
- Access to Google Apps Script.
- A basic understanding of editing configuration settings.
- A legitimate public contact address for your intended recipient.

### Installation

**Step 1: Open Google Apps Script**

Visit:

https://script.google.com/

Sign in with your Google account.

**Step 2: Create a New Project**

Click New Project.

Give your project a name, such as:

Democratic Leadership Accountability Campaign

**Step 3: Add the Script**

Open the default Code.gs file.

Remove the sample code and paste the project script into the editor.

**Step 4: Configure Your Recipients**

Review the recipient configuration.

Replace the example addresses with appropriate public contact addresses for the offices you intend to contact.

Never publish private email addresses, personal information, passwords, or authorization tokens in a public repository.

**Step 5: Customize Your Message**

Edit the message templates to reflect your own opinions and concerns.

Messages should be accurate, respectful, and representative of the person sending them.

**Step 6: Save Your Project**

Click Save.

Give your project a descriptive name.

## Authorization

Google Apps Script requires authorization before it can send email through your Gmail account.

1. Select the appropriate setup function.
2. Click Run.
3. Review Google's authorization request.
4. Grant permissions only if you understand and accept them.

Never authorize code you have not reviewed.

## Automation and Scheduling

Google Apps Script supports time-driven triggers.

Users may configure recurring tasks through the Triggers section of the Apps Script dashboard.

Responsible automation should include:

- Reasonable sending intervals.
- Daily sending limits.
- Manual activation.
- An emergency stop function.
- Monitoring of execution history.

Automation must never be used to overwhelm, harass, or flood public offices.

## Responsible Use Policy

This project exists to encourage civic engagement, not abuse.

### Acceptable Use

Users are encouraged to:

- Contact elected officials about legitimate public policy concerns.
- Advocate for leadership changes.
- Express political disagreement respectfully.
- Demand transparency and accountability.
- Customize messages to reflect their own experiences.
- Participate in peaceful democratic engagement.

### Prohibited Use

This project must not be used to:

- Flood government offices with excessive automated messages.
- Harass, threaten, or intimidate individuals.
- Impersonate other voters or organizations.
- Send deceptive or misleading communications.
- Distribute spam or unsolicited bulk messages.
- Circumvent email provider restrictions.
- Publish private contact information.

## Safety and Safeguards

Responsible implementations should incorporate:

| Safeguard | Purpose |
|---|---|
| Sending limits | Prevent excessive email volume |
| Daily caps | Prevent runaway automation |
| Manual activation | Prevent accidental sending |
| Emergency stop | Allow immediate shutdown |
| Recipient validation | Prevent unintended recipients |
| Message review | Encourage accurate communication |

## Privacy and Security

This project does not require users to publish their personal information.

Users should:

- Keep credentials private.
- Never commit access tokens.
- Avoid publishing personal email addresses.
- Review Google permissions before authorization.
- Keep recipient configurations out of public source code.
- Follow Google's applicable sending limits and policies.
